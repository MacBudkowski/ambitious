# Examples

These are illustrative proposals, not observed model-evaluation results. The type depends on the actual constraint, not on the task category.

## Same request, different ambition

Request: “Help me prepare the weekly customer report.”

- **Speed**, when preparation consumes a day: replace repeated manual compilation with a reproducible report step. Compare turnaround time while checking the same required figures.
- **Depth**, when the figures are disputed: trace metrics to raw records and reconcile definitions. Validate totals against an independent source before changing the presentation.
- **Range**, when the report is accurate but poorly understood: apply information-design techniques, such as progressive disclosure, and test whether readers identify the important change correctly.
- **Altitude**, when the report is intended to prevent surprises: explore an exception-based warning process rather than merely a better weekly artifact. Trial it on historical data before proposing recurring operation.

Do not present all four by default. Ask what this report needs to enable, then show the one or two useful choices.

## Two options with a real tradeoff

“Do you need confidence about why customers leave before committing money, or a useful early warning next week?”

- **Depth:** investigate causal explanations using raw evidence and a defensible study design. More confidence takes time and may still leave uncertainty.
- **Speed:** deliver a simple weekly warning based on available signals. Faster feedback does not establish why churn happens.

The user's answer chooses the direction for this task, not a permanent preference.

## Bounded Range experiment

For a confusing onboarding flow, try a cognitive-walkthrough method from human-computer interaction rather than adding more instructions. Propose a fixed set of critical steps and a short review cap; identify likely decision errors and test revised wording with actual users if authorized. Do not claim that a model simulation proves real user comprehension.

## Quiet skip

“Correct this typo only.” → Correct it. No ambition interview.

“Production is down; restore service.” → Follow incident scope first. Do not delay recovery with a strategy discussion.

“Keep the original scope.” → Continue within it; do not quietly add an experiment.
